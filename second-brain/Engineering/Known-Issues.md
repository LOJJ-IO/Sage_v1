# Known Issues

## Open
- **[backend/retrieval]** Trust threshold (0.35) can refuse genuinely-answerable questions when a document packs multiple topics into one chunk (e.g. a short multi-section doc ingested as a single ~650-token chunk) — a narrow query about one section scores low against the whole mixed-topic chunk even though the answer is right there. Observed: "What is the dress code?" refused (top rerank score 0.14) against a doc whose single chunk covers store hours, dress code, pricing, returns, and discounts all together. Not a bug in the trust-scoring fix (see resolved section) — a separate, likely chunking-strategy question (smaller/more chunks would isolate topics better) or threshold-tuning question. Not investigated further as of 2026-07-19. (since 2026-07-19)
- **[backend]** No `/accounts` router exists yet (list/create/reset-pin/deactivate/reactivate/grant-admin) even though `frontend/src/lib/accounts/api.ts` and the `/organization` page already call those routes — currently only works in the frontend's demo-mode fallback (`isDemoMode()`), not against the real backend. The only way to create a business + first admin user right now is `backend/scripts/seed_dev_business.py`. (since 2026-07-19)
- **[frontend/files]** File tags and bookmarks (`LibraryFile.tags` / `.isBookmarked`) are client-side-only decorations — the backend `File` model has no tags or bookmark columns, so edits don't persist across a page reload once wired to the real backend. (since 2026-07-19)
- **[frontend/auth]** PIN-change flow (`must_change_pin`) isn't built on the backend — `LoginResponse.must_change_pin` is hardcoded `false`. Route guards for protected pages also aren't built yet (carried over from earlier — see [[Current-Context]]).

## Recently resolved

- **[backend/memory]** Upload + `/ask` overlapping Docling/torch + FlashRank MiniLM caused peak RSS ≈ sum of both stacks → OOM / arena / OpenBLAS failures (local + Railway). Fixed without removing ADR-0008 stacks: `.txt`/`.md`/etc. skip Docling; one lazy `DocumentConverter`; process-wide `app.ml_gate.heavy_ml` serializes extract↔rerank; rerank pool 30→14; Dockerfile thread caps. FlashRank model itself stays `ms-marco-MiniLM-L-12-v2` (see next entry — a smaller-model attempt broke grounding). Code mitigations alone still left Railway at 762-927MB peak against its 1GB limit (measured via `railway metrics --memory`) — container still OOM-crashed under two sequential `/ask` calls even after every code fix, matching ONNX Runtime's memory arena growing per-inference and not releasing to the OS. **Fully resolved** once the user upgraded Railway's plan/memory limit to 8GB: same day, 5 sequential + 3 concurrent `/ask` requests all succeeded, peak RSS steady at ~1.17GB (15% of 8GB), zero crashes. Code mitigations were real and worth keeping (lower baseline, better latency, graceful degradation) but the hard ceiling needed an infra fix, not more code. (resolved 2026-07-20)
- **[backend/retrieval]** A same-day attempt to cut FlashRank RAM by swapping `ms-marco-MiniLM-L-12-v2` → `ms-marco-TinyBERT-L-2-v2` shipped to the working tree but was never trust-threshold-tested: `trust.py`'s `evaluate_trust` gates on a fixed `trust_score_threshold = 0.35`, calibrated against MiniLM's score scale. TinyBERT (2 layers vs. MiniLM's 12) scored a textbook-perfect match ("returns allowed within 14 days" for "what is the return policy") at **0.03** — an order of magnitude under threshold — causing false refusals. Caught by `test_relevant_query_proceeds` and `test_every_eval_case_reports_a_retrieval_verdict` before it reached production. Reverted to MiniLM-L-12 same day. **Lesson: never swap the reranker model without re-deriving `trust_score_threshold` via the eval suite in the same change** — a smaller/different cross-encoder's score distribution isn't guaranteed to resemble the one a fixed threshold was tuned against. See [[Lessons-Learned]]. (resolved 2026-07-20)
- **[backend/retrieval]** `rerank()` (`backend/app/retrieval/rerank.py`) only caught exceptions during reranker *model loading*, not during the actual `ranker.rerank(request)` inference call — an ONNX runtime failure mid-inference (e.g. arena allocation failure under memory pressure) crashed the entire `/ask` request into a raw 500 instead of falling back to fusion-score ordering like an unavailable ranker already does. Fixed: wrapped the inference call in the same try/except-and-fallback pattern. (resolved 2026-07-20)
- **[backend/ingestion]** `process_file` (`backend/app/ingestion/pipeline.py`) only flipped a file's status to `"failed"` if `ingest_text` itself threw — but `extract_text`/`storage.download()`, called *before* `ingest_text` even starts, had no equivalent handling. A crash there (e.g. Docling's `DocumentConverter` failing under memory pressure) left the file showing `"pending"` forever with no error recorded and no signal to the admin UI. Fixed: extraction failures now also flip status to `"failed"` with the error message. (resolved 2026-07-20)
- **[backend/agent]** Citation ids used a bare `#{chunk_index}` suffix (e.g. `#5`). Any document whose own text contains a numbered section/heading matching a *different* real chunk index (e.g. "Section 5: Employee Discount" living in chunk `#0`) made the model substitute the in-document section number for the real citation id — **100% reproduction rate** across repeated attempts, confirmed even after an explicit system-prompt instruction not to do this (prompting alone did not fix it). Root-caused via raw OpenRouter response inspection, not guessed. Fixed by changing `citation_id()` (`backend/app/retrieval/assemble.py`) to a short hash suffix instead of the raw integer — nothing in real document text resembles a hash, so there's no plausible number for the model to confuse it with. Confirmed: 6/6 clean, correctly-cited answers after the fix, vs. 0/5 before it, on the exact same question. See [[Lessons-Learned]]. (resolved 2026-07-19)
- **[backend/agent]** `openrouter/auto` (and even the pinned `google/gemini-2.5-flash-lite` model without a provider preference) intermittently routed through OpenRouter's "Google" upstream, where Gemini's forced-function-calling occasionally emitted several duplicate tool calls in one response — Google's own API flags this `MALFORMED_FUNCTION_CALL`, surfaced by OpenRouter as `finish_reason: "error"`. OpenRouter's "Google AI Studio" upstream didn't reproduce it. Fixed by pinning `provider.order: ["Google AI Studio"]` via `ModelSettings(extra_body=...)` in `backend/app/agent/sage_agent.py`. Combined with the citation-hash fix above, this eliminated both distinct failure modes that were making `/ask` unreliable. (resolved 2026-07-19)
- **[backend/retrieval]** **Highest-impact fix of the 2026-07-19 session.** `evaluate_trust`'s `score_hits()` averaged *all* hits `retrieve()` returned (always padded to `top_k=8` regardless of relevance), so a business with more than one document would get a single excellent match (e.g. 0.98) diluted by ~7 near-zero padding hits from unrelated files down to well under the 0.35 refusal threshold — a false "I don't have enough grounded information" refusal on a question that should've worked. Only surfaced once a second file was uploaded (both `test_trust.py` cases only ever ingest one short doc, so it passed). Fixed: `score_hits()` now uses `max(scores)`, matching what `FallbackEvent.top_score`'s column name always implied it should've been. See [[Lessons-Learned]]. (resolved 2026-07-19)
- **[backend/files]** `SupabaseStorage` was missing the `apikey` header Supabase's Storage API requires alongside `Authorization` — every real upload/download/delete 403'd with a misleading "Invalid Compact JWS" error regardless of key validity. Fixed in `backend/app/files/storage.py`. See [[Lessons-Learned#2026-07-19 — Supabase Storage rejects a valid service key without an `apikey` header]]. (resolved 2026-07-19)
- **[backend/agent]** Citation validation failed ~1/3 of requests because the system prompt's own example citation (`"policy.pdf#0"`) looked like a filename instead of the real `{file_id}#{chunk_index}` hex-id format shown in context — the model would substitute a nicer-looking fake id. Fixed the prompt example in `backend/app/agent/sage_agent.py`. See [[Lessons-Learned#2026-07-19 — A system prompt's own citation example can bias the model away from the real format]]. (resolved 2026-07-19)
- **[backend]** Unhandled `ModelHTTPError`/`UnexpectedModelBehavior` from the LLM call crashed `/ask` into an opaque 500 with no JSON body. `answer_question` now catches both and returns a graceful "temporarily unable to answer" `AnswerResult`. (resolved 2026-07-19)
